当前本机配置（2026-11-13 最后更新）：登录启动后用户报告位置和颜色异常。用不加偏移、不改色序的静态图复核，用户明确回复「0，A」，即顶部刻度 0、标准 RGB 行正确。因此当前取消此前的 BRG 和 X=-60 补偿，使用 RGB、X=0、Y=0、270° 旋转、物理帧 gamma=1、saturation=1、背光 100%。用户随后对照聊天与副屏上的同一张人物和色块图，确认「图片很对现在。保持这个配置记住」。当前图片层也恢复原图：亮度 100、饱和度 100、淡化 0。软件配置在复核前没有丢失；设备此次与此前呈现不同结果的底层原因未确定。后文其他参数为历史实验记录，不代表当前配置。原始背景文件未改写。

## 传输与 RGBA 兼容性

屏幕不执行网页。Chrome 渲染本地页面，主机旋转整图到 720×1280，再通过串行化 WinUSB 事务发送。

协议参考 [MIT 实现 ScreenDevice.cs](https://github.com/usausa/turing-smart-screen/blob/ade6bd871aa22430b0061eed890f2cd191c3d276/LcdDriver.TuringSmartScreen/ScreenDevice.cs)，许可声明已保留。500 字节命令体按公开格式填充、DES-CBC 编码并封装为 512 字节，图片数据随后发送。固定协议值不是用户凭据。核心命令为同步 10、PNG 102，亮度接口为 14；源码另保留 JPEG 101 方法，但正常画面路径只用 RGBA PNG。

事务检查写入长度、命令回显和 ACK，并设有限超时。服务单独持有设备句柄，旧会话请求不能写入或关闭新会话。停止保留最后一帧，不代表关屏。

参考设备接受 RGB PNG（color type 2）并返回 ACK，却出现重复条带和旧背景。改用 **RGBA PNG（color type 6）、alpha=255** 后，人工对照确认图像完整、方向正确。可以确认此设备存在 RGB PNG 显示兼容问题；内部是否使用错误像素步长仅属推测。此经验与上游 RGBA 画布一致，不能推断所有型号或固件都相同。

驱动现在主动拒绝 RGB PNG，无硬件测试覆盖 RGB 拒绝、RGBA 接受和尺寸检查。超过 1 MiB 时进一步压缩 PNG，仍超限则报错，不静默切到可能被旧覆盖层遮挡的 JPEG。

### 颜色通道校准

画面完整和颜色正确需要分别核验。2026-11-13，连接到 macOS 的设备出现橘红色显示为蓝色的现象；此前的四角和方向确认没有验证颜色通道。

用户确认六排列校准图的 E 行正确。该行把源图 RGB 编码为 `(B, R, G)`。这是本机实物核验的补偿映射；不能仅凭该映射推断固件内部像素格式，或将其推广到所有同型号设备。单纯交换红蓝没有解决此设备问题。

控制台「显示 → 颜色修正」提供「标准颜色」「交换红蓝」「循环修正 · BRG」。BRG 在原生帧编码前将通道循环排列为蓝、红、绿；RGBA PNG 格式、全不透明 alpha 和旋转保持不变。网页预览及原始图片保持正常 RGB。

设置以 `panel_color_order`（`rgb` / `bgr` / `brg`）保存在本机 `runtime/display-preferences.json`，重启后恢复，不写入屏幕持久设置。默认仍为标准颜色；本机使用经 E 行核验的 `brg`。不按操作系统推断设备色序。

回归测试从实际帧发送入口检查三个模式的像素、旋转位置、alpha=255、PNG color type 6，以及偏好保存和非法值拒绝。校准原图及排列记录保存在本机 `runtime/channel-matrix-source.png` 与 `runtime/channel-matrix-orders.json`。

### 本机位置与色调校准

2026-11-13，用户实物照片显示画面上下环绕错位、颜色过深。静态图与连续投屏均存在错位；改成无行滤波、单 IDAT 的 PNG 后仍有错位。因此没有把更换 PNG 编码当作修复。

用户读到屏幕最上边对应源图刻度 60。对原生 720×1280 帧沿 X 轴循环偏移 -60 像素，在当前 270° 横屏下抵消观察到的向上 60 像素环绕。整图先以 0.8 饱和度处理，再应用 `output = 255 * (input / 255) ** 0.6` 提亮中间调。处理后保持不透明 RGBA，再映射 BRG、旋转和执行原生坐标偏移。用户明确确认静态图「位置正确，颜色合适」。这是本机经验补偿，不是对固件原因的判定。

`panel_calibration.py` 负责全场景物理帧校准。`panel_calibration` 保存在本机 `runtime/display-preferences.json`，当前为 `{"gamma": 0.6, "saturation": 0.8, "offset_x": -60, "offset_y": 0}`。新设备默认 gamma=1、saturation=1、offset_x=0、offset_y=0。偏移采用循环补偿，不裁切页面，也不在网页 CSS 中移动内容。浏览器不应用设备补偿。

目前这是本机校准配置，可由 `/api/control` 提交完整 `panel_calibration` 对象；没有增加网页调节控件。恢复中性设置用 `{"gamma": 1, "saturation": 1, "offset_x": 0, "offset_y": 0}`。伽马范围 0.3–2.0、饱和度 0–2.0、原生 X 偏移 -719–719、Y 偏移 -1279–1279；非法设置不写入偏好。配置不写入屏幕持久设置。

源图不被修改，alpha 强制 255，PNG color type 6。软件测试覆盖四向旋转后的补偿、灰阶提亮、源图保留、参数校验、实际帧入口及偏好恢复。实物确认仅覆盖当前 270° 横屏，其他方向经过软件验证。

## 有限传输测试

### 人物发色复核与保色提亮

在用户选择 01 后，因仍偏暗，将 gamma 从 .6 调成 .45。用户随后提供实物照片：头发呈灰棕色、浅色背景偏青。照片用于判断异常方向；曝光、白平衡、环境光与屏幕观察角度未知，不能直接用照片反推精确面板 ICC 或 RGB 增益。

源图在网页经历饱和度 .7、亮度 1.08、透明度 .72，之后物理帧经历饱和度 .8 和逐通道 gamma。后一曲线本身也会降低彩色像素的饱和度。以橘棕 `(204,120,82)` 为例，物理饱和度 .8、gamma .45 后成为 `(224,184,162)`；这不是源图原有的颜色关系。

新增可选 `panel_calibration.tone_mode="preserve_rgb"`：先应用指定饱和度，再根据 `max(R,G,B)` 计算共用提亮倍率，三通道使用同一倍率，最后四舍五入。共用倍率让最大通道不超过 255，保持 RGB 比例与色相、饱和度，避免逐通道曲线导致额外褪色。灰阶 128 在 gamma .45 下仍提亮为 187。旧配置省略该字段时继续使用原来的 `channels`，默认值和已有配置不变。该模式使用 Pillow ImageMath.lambda_eval，依赖最低版本设置为 Pillow 11。

已生成并发送单张 A–D 人物对照图：A 当前处理；B 去掉网页褪色并恢复饱和度 1；C 在 B 基础上使用保色提亮；D 在 C 上试用 RGB 增益 `(1,.96,.92)`。D 仅是实物比较候选，没有保存为生产配置。对照图仍是 720×1280 RGBA、alpha=255、BRG、原生 X=-60，载荷 922523 字节。正常看板暂停以保留静态对照图，待用户选择后应用并恢复刷新。

测试覆盖色相与饱和度保留、灰阶端点、输入校验、偏好恢复，以及真实帧入口中的 BRG、尺寸和 alpha。用户实物选择尚未记录时，不能把该候选处理称为已验证修复。

### 2026-11-13 颜色复核

用户再次报告颜色异常，因此此前的「颜色合适」只代表当时静态样本，不能认定所有页面已完成色彩校准。

本次实际连接的同步响应含 `turzx_0001_0015`。USB 标识为 `1CBE:0050`，Bulk OUT/IN 为 `0x01/0x81`，包长 512 字节。型号映射对应 5.2 英寸、原生 720×1280。该版本字符串不等同于面板型号。

重新核对了官方 [5.2 英寸详情](https://www.turzx.com/2026/09/11/turzx-5-2-inch-detail/)、[软件下载](https://www.turzx.com/2025/08/07/52_inch/)，以及公开 Python/C# 驱动。公开实现包含亮度命令 14，百分比 0–100 映射到 0–102；还有方向 13、帧率 15、持久设置 125。本次不发送方向、帧率、持久设置或重启命令。查阅资料没有找到可读回的色温、伽马、ICC 配置或色域参数。这不证明固件没有其他私有接口。

三账号页图片原先同时应用 opacity=.72、CSS saturate(.70)、brightness(1.08)，之后整个物理帧又执行 saturation=.8、gamma=.6。因此显示链路确实改变了原图色彩；是否为用户描述的全部原因仍需实物确认。

`panel_color_compare.py build` 离线生成编号 00–06 的固定样例：00 对比六种通道排列；01 重现当前参数；02 去掉图片层滤镜与透明度；03–06 保留原图饱和度，以 gamma=.6/.75/.9/1 对比。所有样例均保留已确认的原生 X=-60 位置补偿。01–06 使用此前确认的 BRG；00 的每行独立排列，不能再次叠加 BRG。

用户明确要求轮播候选图片。本次以 12 秒停留、最多 900 秒执行低频对比，不作为吞吐测试。运行前停止正常服务投屏并验证所有帧；结束或异常时先关闭 USB，再恢复原场景。创建 `runtime/color-comparison/stop` 可提前停止；再次运行前删除该标记。候选参数不覆盖已保存配置。选定参数后仍要在真实账号页核对。

软件验证覆盖 PNG 原生尺寸、color type 6、alpha=255、单帧小于 1 MiB、色序样本，以及异常路径中先释放 USB 再恢复投屏。实物颜色结论由用户反馈决定。
