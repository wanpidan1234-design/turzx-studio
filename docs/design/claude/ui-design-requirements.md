# Claude 账号看板 · UI 设计需求

请设计一套用于桌面副屏的 Claude 账号额度看板。支持 1–5 个账号。用户需要一眼看清每个账号的 **5h 剩余额度、7d 剩余额度和各自的重置时间**，并识别当前使用的账号。

这是一套完整设计交付，包含账号数量变化、横竖屏适配、数据状态和开发标注。

## 产品与画布

| 项目 | 要求 |
| --- | --- |
| 使用场景 | 5.2 英寸桌面副屏，常驻显示，用户扫一眼读取信息 |
| 横屏 | 1280 × 720 px，16:9 |
| 竖屏 | 720 × 1280 px，9:16 |
| 账号数量 | 1、2、3、4、5 个账号均有完整方案 |
| 同页展示 | 所有账号的核心信息同页可见，不依赖滚动、翻页、轮播、悬停或点击 |
| 页面性质 | 只读看板；不设计登录、账号管理、调度设置或切换按钮 |
| 语言与时间 | 中文；北京时间 Asia/Shanghai；24 小时制 |
| 核心风格 | 简洁、清晰、温暖、浅色；数据阅读优先 |

## 参考素材的用途

素材位于同目录 `Claude-UI设计素材/`。

- **用户信息排版参考.png**：参考账号信息的分组和阅读顺序。当前产品已恢复此卡片排版。设计可以调整布局、字号、间距和信息密度，不要求照抄旧卡片尺寸。
- **Claude背景-横屏.png / Claude背景-竖屏.png**：使用的 Claude 人物。保留橙发、金花黑缎带、奶油披肩和黑裙。背景与 UI 必须一起设计。
- **OpenAI画风与位置参考-横屏.png / 竖屏.png**：参考细线条、浅色留白、柔光与人物位置。横屏人物靠右，竖屏人物靠右下。不要改成银发龙娘。
- 人物来源参考：[用户指定的 B 站视频](https://www.bilibili.com/video/BV1oEWj6qExs/)。采用视频中的橙发 Claude，不使用蓝发人物、视频场景、字幕或水印。

不要恢复旧参考图中的针织背心人物。不要在页面四角增加标题、系统信息、时钟或装饰文字。页面不出现 `cswap` 字样。

## 信息层级与内容

| 层级 | 字段 | 展示要求 |
| --- | --- | --- |
| 核心 | 5h 剩余额度 | 大号百分比；明确标注「5h」或「5 小时窗口」 |
| 核心 | 7d 剩余额度 | 大号百分比；明确标注「7d」或「7 天窗口」 |
| 核心 | 两个窗口的重置时间 | 分别紧邻对应额度，不能让用户混淆两个时间 |
| 识别 | 账号名称 | 所有账号可区分；不能仅靠颜色或位置识别 |
| 识别 | 当前账号 | 使用简洁文字标记或文字加图标；不能仅用颜色 |
| 状态 | 数据过期、未知、连接中断 | 靠近受影响的数据，不能被普通装饰弱化 |
| 辅助 | 账号编号、脱敏邮箱、套餐 | 低权重；长文本截断；不得挤压核心数据 |
| 辅助 | 计划时段 | 明确标「计划时段」，不能与实际重置时间混为一谈 |
| 辅助 | 调度或异常说明 | 简短文字；长内容允许截断，关键状态仍需可见 |

额度进度条可以保留，但不是必选。进度条与百分比必须都表示「剩余」，方向一致。不要同时混用「已用」和「剩余」而不加区分。

默认提供重置倒计时与绝对时间，例如「4 小时 21 分后重置」「11/13 16:39 · 北京」。高密度方案可以只保留绝对时间，但每个窗口必须保留一个明确的重置信息。倒计时不显示秒，避免画面跳动。

## 1–5 个账号的适配

请交付 **5 种账号数量 × 2 种方向 = 10 个主画板**。账号数量变化时调整布局，不要将 3 个账号的卡片等比缩小为 5 个。

| 账号数 | 设计重点 |
| --- | --- |
| 1 | 突出单账号的 5h、7d 和重置时间；充分利用留白与人物 |
| 2 | 支持并排比较；两账号视觉权重一致 |
| 3 | 参考所附卡片的信息组织；保证两个窗口的对应关系清楚 |
| 4 | 重新组织网格或行列；核心数字保持清晰可读 |
| 5 | 同页展示全部 10 个额度及其重置时间；优先压缩辅助信息 |

行式、列式或网格式由设计师选择。请标注每种数量的布局规则、边距、间距、字号及辅助字段的显示规则。

账号顺序保持稳定。当前账号变化时只改变标识，不让所有账号重新排序。账号数不足 5 个时，不显示多余空卡片。

## 视觉与背景适配

- 5h、7d 与重置时间必须比邮箱、套餐和计划时段更醒目。
- 数字使用等宽数字特性，更新时不跳位。
- 设计明确的字号梯度，不用所有字段同大同粗。
- 卡片或文字底板使用足够遮罩，保证背景明暗变化时可读。
- 人物面部和主要发饰不被数据遮挡。不得把核心数据直接压在头发和衣服纹理上。
- 账号增加时，可以调整人物大小、裁切和背景位置。保持横屏靠右、竖屏靠右下的构图意图。
- 避免复杂渐变、重阴影、霓虹光效、密集装饰和高噪声纹理。
- 文字与背景建议达到 4.5:1 对比度。不能仅靠红绿颜色表达正常与异常。
- 在原生尺寸下检查，不以放大后的 Figma 画面代替小屏可读性检查。请给出实际字号，重点验证 5 账号画板。

## 数据规则与状态设计

| 情况 | 必须表达的语义 |
| --- | --- |
| 正常 | 显示服务端已用比例的补数，即剩余额度；0% 与 100% 均为有效值 |
| 低额度 | 剩余 ≤ 1% 对应已用 ≥ 99%；显示额度紧张或不可用状态，不暗示已成功切换 |
| 当前账号 | 可以同时出现低额度、旧数据或连接异常；状态不能互相覆盖 |
| 数据过期 | 标注「上次读取剩余」或「旧数据」；保留旧值；不伪装成实时数据 |
| 额度未知 | 显示「—」和明确提示；不显示 0% 或 100% 作为默认值 |
| 重置时间缺失 | 显示「重置时间未提供」；不生成倒计时 |
| 重置时间已到、数据未刷新 | 显示「等待额度更新」；不出现负倒计时，不自动将额度改为 100% |
| 页面连接中断 | 保留已有数据并显示中断提示；提示不覆盖核心额度 |
| 无账号 / 初次加载 | 提供独立空态和加载态；不要伪造账号、额度或计划时段 |
| 名称、邮箱、说明过长 | 给出截断规则；额度和重置时间不得省略 |

3 个现有账号的计划时段为 07:00–12:00、12:00–17:00、17:00–22:00。实际窗口由服务端决定。不能将计划时段结束时间直接当作额度重置时间。第 4、5 个账号的计划时段尚未定义；设计以可配置数据或「未配置」处理，不自行编造时段。

## 交付物

- 可编辑 Figma 文件，含 10 个主画板，以及空态、加载态、异常状态画板。
- 账号组件，含正常、当前、低额度、旧数据、未知等变体，以及状态组合示例。
- 字体、字号、行高、色值、圆角、间距、遮罩、图标规范。
- 1–5 个账号的布局规则和横竖屏切换规则。
- 背景裁切、人物安全区域和文字区域标注。
- 原生尺寸 PNG 预览，以及需要独立导出的插画、图标资源。
- 开发交接说明，写明辅助信息的取舍顺序和长文本规则。

## 验收标准

1. 10 个主画板全部覆盖，1–5 个账号都能同页读取全部核心额度和重置时间。
2. 用户能直接区分 5h 与 7d、当前账号、剩余额度与重置时间。
3. 正常、旧数据、未知与已耗尽有明确差异。
4. 5 账号布局没有文字重叠、越界、隐藏核心字段或缩字堆叠。
5. 背景与信息布局协调，人物脸部无遮挡，核心数据不受背景干扰。
6. 页面没有四角附加信息、工具名称或无关装饰文案。
7. 所有布局和状态均可用 HTML/CSS 实现，不依赖悬停和滚动读取核心信息。

工程导出由开发处理：网页保持正常 RGB；设备帧使用 720×1280 RGBA、alpha=255、PNG color type 6，完整帧小于 1 MiB。设计源文件不要交换颜色通道，也不要烘焙文字到人物背景。
